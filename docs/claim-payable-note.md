# หมายเหตุถึงฝ่ายบัญชี — บัญชีเจ้าหนี้ค่าชดเชย (CLAIM_PAYABLE)

**สถานะ:** ต้องอ่านก่อนเปิดใช้เอกสารประเภทที่ตั้ง `accrues_on_approval`
**เขียนเมื่อ:** 2026-07-27

## เกิดอะไรขึ้น

เอกสารประเภทที่ตั้งธง "รับรู้ค่าใช้จ่ายตอนอนุมัติ" จะลงบัญชีทันทีที่อนุมัติครบทุกขั้น
ไม่รอการจ่ายเงิน:

```
   ตอนอนุมัติครบ
   Dr  ค่าใช้จ่าย (ตามบัญชีที่งบก้อนนั้นผูกไว้)     4,500
       Cr  เจ้าหนี้ค่าชดเชย (CLAIM_PAYABLE)            4,500
```

เหตุผล: ภาระเกิดขึ้นแล้วตั้งแต่วินาทีที่อนุมัติ และจำนวนเงินก็แน่นอนแล้ว ส่วนการจ่ายเงินเป็นเพียง
การชำระหนี้ที่เกิดไปแล้ว รูปแบบเดียวกับ GRNI ที่คั่นระหว่างรับของกับจ่ายเงิน

## ขาที่สองมาแล้ว — แต่ไม่ย้อนหลัง

**อัปเดต 2026-07-27:** ระบบบันทึกการจ่ายได้แล้ว เมื่อการเงินบันทึกการจ่ายพร้อมแนบหลักฐาน
ระบบจะลงขาที่สองให้อัตโนมัติในรายการเดียวกัน:

```
   Dr  เจ้าหนี้ค่าชดเชย   4,500
       Cr  เงินสด/พักจ่าย     4,500
```

การบันทึกและการลงบัญชีอยู่ในทรานแซกชันเดียวกัน — ถ้าลงบัญชีไม่ได้ (เช่นยังไม่ได้ map
`CASH_CLEARING`) ระบบจะไม่บันทึกการจ่ายเลย ไม่มีสภาพครึ่ง ๆ กลาง ๆ

**⚠️ แต่เคลมที่อนุมัติไปก่อนหน้านี้ไม่ได้ถูกล้างย้อนหลัง** — เอกสารที่อนุมัติก่อนวันที่ระบบมี
ฟังก์ชันนี้ มีแต่ขาแรกค้างอยู่ ต้องล้างด้วย JV มือ

**และคิววันแรกจะยาว** — รายการ "อนุมัติแล้วยังไม่จ่าย" ที่ระบบแสดงจะรวมเคลมเก่าทั้งหมด
ไม่ใช่แค่งานของวันนั้น ต้องเคลียร์ของเก่าก่อนถึงจะใช้เป็นคิวงานประจำวันได้

**สิ่งที่ต้องทำ:**
1. ล้างเจ้าหนี้ของเคลมที่อนุมัติก่อนวันนี้ ด้วย JV โดยกระทบยอดกับ statement ธนาคาร
2. จากนั้นใช้การบันทึกการจ่ายในระบบทุกใบ ยอดเจ้าหนี้จะล้างตัวเองไปเรื่อย ๆ

## ก่อนเปิดใช้ ต้องตั้งค่าอะไร

1. สร้างบัญชีเจ้าหนี้ค่าชดเชยในผังบัญชีของบริษัท (ประเภทหนี้สิน)
2. map `account_role` ของบริษัทนั้น: `CLAIM_PAYABLE` → บัญชีที่สร้าง
3. map `CASH_CLEARING` ด้วย — ใช้ตอนบันทึกการจ่าย ถ้าไม่มีจะบันทึกการจ่ายไม่ได้เลย
4. ตรวจว่างบที่เอกสารประเภทนี้ตัด ผูกกับบัญชีค่าใช้จ่ายที่ถูกต้อง (`budget.account_id`)

**ถ้ายังไม่ได้ map `CLAIM_PAYABLE`** ระบบจะไม่ลงบัญชีให้ แต่เอกสารยังอนุมัติสำเร็จและงบยังถูกตัด
ตามปกติ — ความผิดพลาดจะปรากฏเป็น log ระดับ ERROR เท่านั้น ไม่มีใครเห็นบนหน้าจอ เพราะฉะนั้น
**ต้อง map ให้เสร็จก่อนเปิดใช้จริง** ไม่ใช่ค่อยมาไล่ทีหลัง

## ⚠️ ตัวเลขที่ตั้งไว้ตอนนี้เป็นของสมมติ ต้องยืนยัน

ระบบเปิดใช้ได้แล้วด้วยค่าที่ตั้งไว้ชั่วคราว เพื่อให้ระบบเคลมเริ่มส่งงานเข้ามาทดสอบได้ก่อน
**ทั้งสี่ค่านี้ยังไม่มีใครอนุมัติ** ถ้าปล่อยไว้แล้วขึ้นใช้จริง แปลว่าธุรกิจยอมรับมันโดยปริยาย

| ค่า | ตั้งไว้ตอนนี้ | หมายความว่า |
|---|---|---|
| งบชดเชยทั้งปี 2026 | 100,000,000 กีบ | เกินนี้เอกสารจะ **ถูกปฏิเสธตอนส่ง** (HARD_STOP) ไม่ใช่แค่เตือน |
| ขั้นที่ 1 | ตั้งแต่ 0 กีบ | หัวหน้าศูนย์รับเคลมอนุมัติคนเดียวจบ |
| ขั้นที่ 2 | ตั้งแต่ 1,000,000 กีบ | เพิ่มผู้จัดการงบประมาณ |
| ขั้นที่ 3 | ตั้งแต่ 10,000,000 กีบ | เพิ่มประธาน |

**ขั้นที่ 1 ต้องเริ่มที่ 0 เสมอ** ห้ามเปลี่ยนเป็นเลขอื่น เคลมที่ต่ำกว่าขั้นต่ำสุดจะส่งได้ จองงบไปแล้ว
แล้วไม่เจอขั้นอนุมัติที่ใช้ได้ ระบบจะเขียน log ทิ้งไว้เงียบ ๆ และเอกสารค้างสถานะ SUBMITTED ตลอดไป
พร้อมงบที่ถูกกันไว้และไม่มีใครได้รับแจ้ง

แก้ได้ที่หน้าจอตั้งค่า (งบ / สายอนุมัติ) ไม่ต้องแก้โค้ด — ค่าที่เห็นข้างบนมาจากสคริปต์ตั้งค่าเริ่มต้น
`back/scripts/setup-claim-dev.ts` ซึ่งจะไม่เขียนทับของที่มีอยู่แล้ว

## ตรวจสอบภายหลังได้จากไหน

รายการที่ระบบลงให้จะมี `source_type = 'APPROVAL_ACCRUAL'` และ `source_id` เป็นรหัสเอกสาร
หนึ่งเอกสารมีได้หนึ่งรายการเท่านั้น (บังคับด้วย unique key) จึงไม่มีทางลงซ้ำ
